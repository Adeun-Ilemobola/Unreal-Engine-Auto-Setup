# Process supervision design

An exclusive canonical-descriptor directory is created before spawn. Its immutable intent includes a random operation ID and project identity. The encoded command is tagged with that ID and its SHA-256 is persisted before launch. The packaged helper binary and source hashes must match the build manifest.

The native bootstrap starts an independent worker using CREATE_BREAKAWAY_FROM_JOB, a new process group, no window and no inherited handles. Denial fails closed. This step is necessary because the first direct-child implementation died with the development host on reload. It is distinct from the managed work job: the worker's private, unnamed job enables kill-on-last-handle-close and disables both breakaway modes.

The worker creates PowerShell suspended, attaches it to that private job before resuming, and retains root/job handles. Child work inherits job membership. File handles carry stdout/stderr into the claim directory. The worker samples job accounting every 50 ms; retained root exit plus active process count zero authorizes a flushed, atomically renamed completion receipt. A completion-port notification or a missing PID is insufficient. The host tails bounded logs and accepts only receipts matching project, operation, helper and command digest, exact containment version, zero active count, root exit and typed result fields.

Host disposal detaches listeners/streams; it does not cancel supervised work or authorize regeneration restoration. New hosts can recognize the current helper using executable, PID, creation time and operation directory, or consume durable completed proof. The claim release path obtains an exclusive lock, revalidates proof, atomically retires the claim, then deletes only that retired directory. Crashes leave conservative residue.

Cancellation writes an operation/digest-bound request. The running worker calls TerminateJobObject on its private handle; request acceptance and verified completion are separate. Duplicate requests are harmless. A supervisor crash closes the last job handle and kills contained work, but absence of durable completion still blocks recovery. Recovered PID-based cancellation is not implemented.

The worker exits and closes kernel/file handles after completion. The host disposes stream listeners and terminal emitters when its operation finishes; log tails are bounded, and startup/identity diagnostics are bounded per operation. There is no production global process scanner. Completion removes normal journals; uncertainty does not expire. Output above 64 MiB fails closed and retains the claim.

This boundary covers descendants of trusted local UBT execution. Builds pass `-NoUBA -NoXGE -NoFASTBuild -NoSNDBS` to exclude known brokered executors. WMI/service-mediated process creation and malicious same-user mutation are not contained by this model. See Microsoft's [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [nested jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs), and [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject) documentation. These limits are why the implementation does not claim universal process ownership.
